# 植物大战僵尸 · 三十旗 1-1 改版

把《植物大战僵尸》的 **1-1 关卡**重构为 **30 面旗的长线生存挑战**：
开局即全卡 + 10 槽 + 模仿者，每面旗解锁新的战场行、新僵尸、新机制；
旗与旗之间进行三选一肉鸽强化；僵尸随旗次指数增强，植物同步获得机制型成长。

## 玩法

**下载本仓库后，直接运行 `Release/PlantsVsZombies_Play.exe` 即可开始**
（运行依赖 `main.pak`、`bass.dll`、`properties/` 已随仓库附带）。

进入方式：**冒险模式 1-1 的战斗中按 `T`**（弹出确认框后进入三十旗）。

| 操作 | 说明 |
| --- | --- |
| `T` | 冒险 1-1 战斗中进入三十旗关卡 |
| `空格` | 暂停 / 继续 |
| `1` ~ `9` | 快捷选择卡槽 |
| `1` / `2` / `3` | 强化三选一弹窗里直接选第 1 / 2 / 3 张（弹窗会抢走键盘焦点，此前只能鼠标点） |
| `Backspace` / `Delete` | 清除三十旗存档，从第 1 面旗重来 |

**进度存档**：直接复用原版的存档机制（`SyncBoard` 整块写盘），每清一旗自动保存一次，
退出游戏也会保存——场上植物、阳光、小推车、地形与强化层数全部保留。
再次进入三十旗时会弹出原版「继续游戏 / 新游戏」对话框。

**核心循环**：每面旗 = 一批波次（数量随旗次递增）→ 旗间三选一强化（普通 / 稀有 / 史诗 / 传说）
→ 下一面旗解锁新的行、僵尸与机制。

- 第 1–3 面旗只有正中一行草皮，战场逐旗展开：第 4 旗 2 行、第 8 旗 3 行、第 13 旗 4 行、第 18 旗 5 行并让两端转水路
- 每次行扩展时会自动为那一行补放小推车（原版从第 2 旗起不再建车，需要自己接）
- 僵尸血量全程成长（起步更高 + 每旗递增），第 16 旗起出现精英，第 5 旗起出现巨人等重装单位
- 玩家侧同步强化：主力植物获得专属机制（穿透 / 连击 / 溅射 / 元素火球 / 叠种……）

## 实现原理

这是《植物大战僵尸》1.0.0.1051 的**反编译重建工程**——`src/` 是可编译、可运行的 C++ 源码
（不是内存注入、不是资源替换、不是外部补丁）。因此所有改动都落在游戏自己的代码路径上。

### 关卡是怎么造出来的

**1. 新增一个完整游戏模式，而不是改地图**

在引擎里追加 `GAMEMODE_THIRTY_FLAGS`（`GameMode` 枚举 + 挑战表条目），
全工程以 `ThirtyFlagsMode()` 单点判定；**非本模式时所有钩子立即早退，零开销**——
原有玩法不受任何影响。

**2. 入口复用原版启动链**

改编从"冒险 1-1 按 T 弹确认框"进入：新模式的关卡、选卡、过场全部由原版流程创建，
自制内容只在流程的**稳定插入点**接管。这样避开了"在旧关卡中途切换"会造成的状态撕裂
（这类问题曾反复出现：初始化未完成就切换、过场结束回调把模式重置等）。

**3. 让原版静态场地变动态**

原版关卡地形固定，三十旗每面旗动态改写战场：按旗解锁行（未解锁行铺黑幕，同时**出怪也过滤到已解锁行**，
否则玩家无法防守）、随机水路与地形、随机卡池与卡槽组合。

**4. 波次引擎与旗间循环**

覆盖原版的波次生成，产出长线波表；游戏循环按当前旗次校正"每旗应有的波数"。
每面旗结束插入旗间阶段，弹出三选一强化，选择后写入强化池。

**5. 强化系统"通道化"**

几十条强化不散落在各处，而是汇总为少数几个通道：伤害倍率、攻速倍率、僵尸血量曲线。
游戏逻辑只在这些通道上单点消费——**改一条强化 = 改一个通道**，互相不打结，
也便于数值调整与问题定位。

**6. 元素火球**

对原版投射物系统做字段级扩展：冰、极寒、毒、魅惑、黄油、巨大等元素。
火炬点燃豌豆时随机赋予元素，命中效果统一挂在伤害结算的公共路径上
（直伤与溅射都能吃到，避免"只有一种弹道生效"的坑）。

**7. 精英僵尸**

在既有僵尸体系上加一层：躯体染色 + 词条（玻璃炮 / 铁壁 / 迅捷 / 再生……）+ 血量倍率 + 出场警告。

**8. 一条硬约束：绝不改结构体大小**

游戏存档按整个 Board 结构的内存大小写盘，给僵尸或投射物加哪怕一个成员都会破坏存档兼容。
所以所有"每个单位一份状态"的需求（标记、控制冷却等）都用
**文件级静态表 + 单位 ID 索引 + 超时清理**实现——这是本工程最反复用到的技巧。

### 用的什么工具

| 工具 | 用途 |
| --- | --- |
| **MSVC (x86) + Windows SDK** | 编译（工程以 MultiByte 编码编译） |
| **手工构建脚本** | 驱动编译器与链接器（部分环境禁止 MSBuild 执行） |
| **MinGW g++** | 语法级快速检查（用 shim 映射 MSVC 方言） |
| **自建调试层** | 日志 / 断言 / 崩溃转储，Release 下同样生效 |
| **流程日志** | 记录波次、换旗、引擎阶段——定位"卡在哪一步"的第一工具 |
| **Python 字节级脚本** | 安全批量修改 GBK 源码（绝不整文件转码） |

### 一个编码约定（本工程特有）

`src/**` 现有源码是 **GBK（代码页 936）**、以 MultiByte 编译：**只能用字节级工具修改**。
整文件 decode→encode 会把中文注释变成替换字符，编译器在 CP936 下会由此**吞掉行尾甚至下一行**，
引出一大片"变量未声明"之类的假错——这类坑在本工程出现过多次，新增文件一律保持纯 ASCII。
