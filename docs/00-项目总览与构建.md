## 1. 项目是什么

本工作区是 **《植物大战僵尸》(Plants vs. Zombies, PopCap 2009 PC 版)** 的完整 C++ 反编译重建工程，`Release\PlantsVsZombies.exe` 为已产出的可运行成品。代码结构完整保留了原版的类名、函数签名与数据表，并在此基础上添加了少量中文注释与现代化适配（VS2019 工程、C++17 语法糖）。

工程包含游戏的**全部核心玩法逻辑**：冒险模式、迷你游戏、解谜模式、生存模式、禅境花园、商店、图鉴、存档等；以及 PopCap 自研的 **SexyApp 框架**（渲染/控件/声音/资源管理）与 **TodLib** 通用游戏库。

## 3. 编译系统

### 3.1 解决方案

`src\LawnProject.sln`（Visual Studio 2019 格式，工具集 **v143**，VS2019/VS2022 均可打开）：

| 工程 | 类型 | 组成 | 输出 |
|---|---|---|---|
| **Lawn** (`Lawn\Lawn.vcxproj`) | 应用程序 exe | `Lawn\*.cpp` + `TodLib\*.cpp` + 资源脚本 | `..\Release\PlantsVsZombies.exe`（Win32）/ `Debug\` |
| **SexyAppBase WideString** (`SexyAppFramework\SexyAppBase WideString.vcxproj`) | 静态库 | `SexyAppFramework\*.cpp` + `PakLib\PakInterface.cpp` + `ImageLib\*` + 全部第三方编解码 | 供 Lawn 链接 |

> 注意：工程名为 `PlantsVsZombies`（`<ProjectName>` 标签），`OutDir = $(SolutionDir)..\$(Configuration)\`。

### 3.2 关键编译配置

| 配置 | 平台 | 字符集 | 宏 | 运行时库 | 子系统 |
|---|---|---|---|---|---|
| Release\|Win32 | x86 | **MultiByte**（对应 GBK 源码） | `_USE_WIDE_STRING; WIN32; NDEBUG; _CONSOLE` | /MT | Windows |
| Debug\|Win32 | x86 | MultiByte | `_USE_WIDE_STRING; WIN32; _DEBUG; _CONSOLE` | /MTd | Windows |
| Release/Debug\|x64 | x64 | Unicode | `NDEBUG; _CONSOLE`（无 `_USE_WIDE_STRING`） | — | Console |

链接库：`kernel32 user32 gdi32 winspool comdlg32 advapi32 shell32 ole32 oleaut32 uuid odbc32 odbccp32 Winmm Ws2_32`（BASS/FMOD 动态加载，故无静态音频库依赖）。

### 3.3 构建与运行步骤

1. 用 **VS2019 或 VS2022** 打开 `src\LawnProject.sln`；
2. 配置选择 **Release | Win32**（x64 配置为实验性，缺 `_USE_WIDE_STRING` 宏）；
3. 生成解决方案 → 产出 `Release\PlantsVsZombies.exe`；
4. **资源文件**：将游戏资源 `main.pak`、`properties\` 目录（含各 `.xml` 资源定义）放在 exe 同目录（`Release\` 下），原版资源包未包含在本仓库中（版权原因，需自行取得）；
5. 运行 exe。存档写入用户目录（`SaveGame.cpp` 管理）。

> 反编译工程存在大量未初始化变量、指针算术等原版特征；构建时建议保留工程默认的 `/permissive-` 关闭（`ConformanceMode=false`）与警告屏蔽（`26495;26812`），不要开启 `/WX`。

## 4. 源码编码：GBK（重要）

- 所有 `src\**` 下的源码是 **GBK/GB2312（代码页 936）** 编码，VS 工程以 `MultiByte` 字符集配合；
- 在 VS 中打开：若中文注释乱码，将文件编码识别为「简体中文(GB2312)」；
- 脚本/工具处理时使用 `[System.Text.Encoding]::GetEncoding(936)` 或 `iconv -f GBK -t UTF-8`；
- 本仓库的 `LawnCommon.h` 等文件已被前人在头文件处补了带 ★ 的中文分节注释，说明有人做过整理工作。

## 5. 代码风格特征（反编译痕迹）

1. **匈牙利命名**：`theX`（参数）、`aX`（局部）、`mX`（成员）、`gX`（全局）、`NUM_X`（数量常量）、`SEED_/ZOMBIE_`（枚举前缀）；
2. **成员偏移注释**：`//+0x768` 表示相对对象首地址的字节偏移（IDA/反编译还原痕迹，有助于比对原版二进制）；
3. **断言宏**：`TOD_ASSERT(...)`（TodDebug.h），异常捕获用 SEH（`SEHCatcher`）；
4. **结构体即数据表**：`gPlantDefs[]`、`gZombieDefs[]`、`gChallengeDefs[]` 三个巨型静态数组是玩法数值的「数据库」（详见模块文档）；
5. 字符串：`SexyString = std::wstring`（`_USE_WIDE_STRING` 宏时），资源 ID 走 `Resources.h` 大枚举。

## 7. 数据驱动设计一览（修改玩法的入口）

| 数据 | 位置 | 内容 |
|---|---|---|
| `gPlantDefs[]` | `src\Lawn\Plant.cpp` 顶部 | **53 种**植物的全部数值（类型/图像/动画/卡片位/阳光成本/冷却/子类/发射速率），schema 为 `PlantDefinition`（9 字段） |
| `gZombieDefs[]` | `src\Lawn\Zombie.cpp` 顶部 | **33 种**僵尸的数值（`NUM_ZOMBIE_TYPES=33`），schema 为 `ZombieDefinition` |
| `gChallengeDefs[]` | `src\Lawn\ChallengeScreen.cpp` 顶部 | **72 条**游戏模式定义（冒险/生存 15/挑战 20/附加 15/解谜 20/其余 2） |
| `gZombieAllowedLevels[]` | `src\Lawn\Challenge.cpp` 顶部 | 每种僵尸可出现的关卡范围 |
| `properties\*.xml` | 游戏资源目录（不随源码分发） | REANIM 动画、粒子、字体、界面布局等资源描述 |
| `Resources.h` | `src\Lawn\Resources.h` | 资源 ID 枚举（1325 行，628 项 = 440 图像 + 21 字体 + 167 音效） |
| 波次生成 | `Challenge::InitZombieWaves / PickZombieWaves` | 关卡波次**程序化生成**（本工程无静态波次表） |
