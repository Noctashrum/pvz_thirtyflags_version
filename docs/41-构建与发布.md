# 41 · 构建与发布（双版本）

> 本项目在同一份源码上产出**两个 exe**：
> **调试版**（带全部日志/HUD，供后续迭代）与**游玩版**（零调试输出，供分发）。
> 两者通过编译宏区分，obj 分开存放，互不污染。

---

## 一、两种构建模式

`tools/build_manual.py`（绕过被安全策略禁用 MSBuild 的手工构建脚本）：

```bash
# 调试版（默认）—— 保留全部日志/HUD
#   输出：Release\PlantsVsZombies.exe
python tools/build_manual.py

# 游玩版 —— 关闭全部调试输出
#   输出：Release\PlantsVsZombies_Play.exe（与调试版共享同目录游戏资源）
python tools/build_manual.py --player
```

**两者对比**：

| | 调试版 | 游玩版 |
| --- | --- | --- |
| 编译宏 | 无 | `-DTF_PLAYER_BUILD -DPVZ_DEBUG_ENABLED=0` |
| obj 目录 | `src/Lawn/Release/` | `src/Lawn/ReleasePlayer/` |
| 输出 | `Release\PlantsVsZombies.exe` | `Release\PlantsVsZombies_Play.exe` |
| PvzDebug（断言/崩溃转储/日志） | 开 | **整体编译移除**（zero-cost） |
| `TFLog` 文件日志 | 写 `thirtyflags_flow.log` | **空实现** |
| 左上角调试 HUD | 显示 | **不绘制** |
| `TfLogWrite` 阶段日志 | 写 | **空实现** |

**注意**：
- 两种模式的 obj **不可混链**（编译宏不同），脚本已按模式分目录；
- 游玩版首次构建需**全量编译**（`ReleasePlayer/` 为空时约 1~2 分钟）；
- 资源脚本产物（`*.res`，图标/清单段）会从调试版目录自动复制到游玩版目录。

## 二、构建开关（代码层）

`src/Lawn/ThirtyFlags.h` 顶部有完整说明：

```cpp
//   TF_PLAYER_BUILD     —— 游玩版：关闭 TFLog / 调试 HUD / TfLogWrite
//   PVZ_DEBUG_ENABLED=0 —— PvzDebug 模块整体编译移除（TodLib/PvzDebug.h 的 master switch）
```

**新增调试输出时的约定**：
- 临时诊断插桩用 `TFLog("...")`（游玩版自动 no-op，调试版写 `Release/thirtyflags_flow.log`）；
- 定位完成后**记得删除插桩**（上一轮曾在 10 个文件里留了 28 处，清理后 exe 小了 1.5KB）；
- 结构性日志（换旗/波次/弹窗）保留在 `ThirtyFlagsBoardUpdate` 等稳定位置。

| 设施 | 位置 | 产物/用法 |
| --- | --- | --- |
| **PvzDebug** | `src/TodLib/PvzDebug.h/.cpp` | `Release/pvzdebug.log` + `pvzdebug.ini`；断言/崩溃转储，Release 下也生效 |

## 四、源码编码约定（务必遵守）

| 范围 | 编码 | 说明 |
| --- | --- | --- |
| `src/**` 已有 `.h/.cpp` | **GBK（936）** | 工程以 MultiByte 编译；**只能用字节级工具改**，整文件 decode→encode 会把中文注释变 U+FFFD，MSVC 在 CP936 下会吞行导致大片假错 |
| 新增源文件 | **纯 ASCII** | 如 `PvzDebug.h/.cpp`，避免与 GBK 混在一个编译单元 |
| `docs/**` | UTF-8 | — |
| `Release/properties/LawnStrings.txt` | **UTF-16 LE + BOM** | 改错会导致启动黑屏 |
| 源码里的中文字符串 | GBK 字节转义 `"\xa3\xbf..."` | 绕开 bytes 字面量限制（先 python 生成 hex） |

**锚点修改铁律**：改代码前**先 dump 真实字节**（`repr()`），不要凭印象写缩进/空格——
曾因「4 个空格写成 3 个」和「LF/CRLF 混淆」静默失配多次。

## 五、GitHub 发布准备

**已就绪**：仓库根的 `.gitignore`（忽略 obj/pdb/log/exe/dll/`.workbuddy/` 等）。

**建议的分发方式**：
1. **源码仓库**：直接 push（`.gitignore` 已排除全部构建产物）；
2. **可玩版本**：走 **GitHub Releases**：
   - 打 tag（如 `v1.0-thirtyflags`）；
   - 附件打包 `Release/` 目录中**游戏必需的资源 + 游玩版 exe**：
     - `PlantsVsZombies_Play.exe`
     - `properties/`（含 `LawnStrings.txt`）
     - `*.pak` 等原版资源
     - 依赖的 `.dll`
   - **不要**把 exe/资源提交进 git 历史（体积 + 版权）。

**版权提醒**：原版《植物大战僵尸》的资源文件版权归 PopCap/EA，公开仓库建议**只放代码与文档**，
资源在 Release 说明中提示用户自备，或发布为不公开的私有仓库。
