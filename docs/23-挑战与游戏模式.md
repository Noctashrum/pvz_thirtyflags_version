# 挑战与游戏模式模块文档

> 所属: src/Lawn | 文件: Challenge.* / ChallengeScreen.* / ReanimationLawn.*

---

## 1. 模块职责

本模块是《植物大战僵尸》除「冒险模式主线关卡流程」之外**所有游戏模式的总控制器**，覆盖四大块内容：

| 职责 | 载体文件 | 说明 |
|------|----------|------|
| 游戏模式运行时控制 | `Challenge.h` / `Challenge.cpp` | `Challenge` 类，每局游戏一个实例（挂在 `Board::mChallenge` 上），负责关卡初始化、僵尸波次程序化生成、特殊玩法（保龄球 / 我是僵尸 / 砸罐子 / 消灭松鼠 / 智慧树 / 传送门 / 老虎机 / 雨夜 / 墓地危机等）的逐帧更新与胜负判定 |
| 挑战/小游戏选择界面 | `ChallengeScreen.h` / `ChallengeScreen.cpp` | `ChallengeScreen` 类 + 全局 `gChallengeDefs` 大表，负责 4 个页面（生存/挑战/附加关/解谜）的按钮布局、解锁判定、奖杯进度与悬停提示 |
| 动画重绑定（静态帧缓存） | `ReanimationLawn.h` / `ReanimationLawn.cpp` | `ReanimatorCache` 类，把植物/僵尸/割草机的 Reanim 动画**预渲染成 MemoryImage 位图**（供种子包图标、年鉴等静态缩略图使用），并处理植物「变体」（金盏花颜色、模仿者、禅境花园、水族箱） |

**关键设计**：`Challenge` 类不自己维护出怪列表，而是通过 `InitZombieWaves()` 设置 `Board::mZombieAllowed[]`（允许出场的僵尸类型白名单），真正的波次填充算法在 `Board::PickZombieWaves()` / `Board::PickZombieType()`（见 §8）。`Challenge` 负责的是「这个模式允许哪些僵尸 / 特殊规则是什么 / 特殊模式每帧做什么」。

## 2. ChallengeDefinition 结构（字段含义表）

定义于 `ChallengeScreen.h:74-84`。这是挑战选择界面数据表的 schema（**不含**任何运行时逻辑，纯粹是「一条挑战记录」）。

| 字段 | 类型 | 含义 |
|------|------|------|
| `mChallengeMode` | `GameMode` | 该条目对应的游戏模式枚举值（`GAMEMODE_SURVIVAL_*` / `GAMEMODE_CHALLENGE_*` / `GAMEMODE_SCARY_POTTER_*` / `GAMEMODE_PUZZLE_I_ZOMBIE_*` 等） |
| `mChallengeIconIndex` | `int` | 缩略图在贴图集 `IMAGE_SURVIVAL_THUMBNAILS` 或 `IMAGE_CHALLENGE_THUMBNAILS` 中的**单元帧索引**（cel index），用于绘制按钮图标 |
| `mPage` | `ChallengePage` | 所属页面：`CHALLENGE_PAGE_SURVIVAL`(生存) / `CHALLENGE_PAGE_CHALLENGE`(挑战) / `CHALLENGE_PAGE_LIMBO`(附加/隐藏关) / `CHALLENGE_PAGE_PUZZLE`(解谜) |
| `mRow` | `int` | 按钮在页面上的**行**（0 起，每页 5 行） |
| `mCol` | `int` | 按钮在页面上的**列**（0 起，每页 5 列，5×5=25 格） |
| `mChallengeName` | `const SexyChar*` | 名称字符串资源键（形如 `_S("[WALL_NUT_BOWLING]")`），经 `TodStringTranslate` 翻译显示 |

辅助全局函数：

```cpp
ChallengeDefinition& GetChallengeDefinition(int theChallengeMode);
// ChallengeScreen.cpp:190 —— 越界断言 + 一致性断言后直接返回 gChallengeDefs[theChallengeMode]
// 断言逻辑：mChallengeMode == theChallengeMode + GAMEMODE_SURVIVAL_NORMAL_STAGE_1
// 即数组下标 0..71 恰好一一对应 GameMode 枚举 1..72（下标 = 枚举值 - 1，因为 GAMEMODE_ADVENTURE=0 不入表）
```

## 3. gChallengeDefs 数据表分析

定义于 `ChallengeScreen.cpp:12-85`，地址 `0x6A2BA0`。

- **数组长度**：`NUM_CHALLENGE_MODES`（`= NUM_GAME_MODES - 1 = 73 - 1 = 72`）
- **实际初始化条目数**：**72 条**（与数组长度完全一致，下标 0..71 全部显式初始化）
- **索引方式**：`gChallengeDefs[i]` 对应 `GameMode` 枚举值 `i + 1`（即跳过枚举值 0 的 `GAMEMODE_ADVENTURE`）

### 3.1 按页面分布

| 页面 | 条目数 | 内容 |
|------|--------|------|
| `CHALLENGE_PAGE_SURVIVAL` | 15 | 生存模式：普通 5 关 + 困难 5 关 + 无尽 5 关（其中无尽第 3 关标在 SURVIVAL 页，其余无尽在 LIMBO 页） |
| `CHALLENGE_PAGE_CHALLENGE` | 20 | 20 个迷你游戏（战争与豌豆/坚果保龄球/老虎机/种子雨/宝石迷阵…最终决战） |
| `CHALLENGE_PAGE_LIMBO` | 15 | 附加/隐藏关（坚果艺术画/阳光灿烂/无草皮/大块头/向日葵艺术画/空袭/冰冻/禅境花园/高重力/墓地危机/挖啊挖/暴风雨夜/蹦极闪电战/松鼠/智慧树）+ UPSELL/INTRO |
| `CHALLENGE_PAGE_PUZZLE` | 20 | 解谜：砸罐子 1-9 + 无尽(10) + 我是僵尸 1-9 + 无尽(10) |
| 备注 | 2 | `GAMEMODE_UPSELL`、`GAMEMODE_INTRO` 也占用条目（列在 LIMBO 页，仅供内部/升级引导使用，不显示给玩家） |

> 合计 15 + 20 + 15 + 20 + 2 = **72**。与 `ChallengeScreen::Draw` 中奖杯总数（生存 10 / 挑战 20 / 解谜 18）的差异在于：无尽生存、无尽砸罐子、无尽我是僵尸以及 LIMBO 页条目不参与奖杯计数。

### 3.2 典型条目示例（字段顺序：GameMode | icon | page | row | col | name）

```cpp
// 普通生存（第 1 关，第 0 行第 0 列，图标 0）

// 坚果保龄球（挑战页第 0 行第 1 列，图标 6）
{ GAMEMODE_CHALLENGE_WALLNUT_BOWLING, 6, CHALLENGE_PAGE_CHALLENGE,   0, 1, _S("[WALL_NUT_BOWLING]") },

// 我是僵尸第 1 关（解谜页第 2 行第 0 列，图标 11）
{ GAMEMODE_PUZZLE_I_ZOMBIE_1,         11, CHALLENGE_PAGE_PUZZLE,      2, 0, _S("[I_ZOMBIE_1]") },

// 禅境花园（附加页第 1 行第 2 列，图标 7）
{ GAMEMODE_CHALLENGE_ZEN_GARDEN,      7,  CHALLENGE_PAGE_LIMBO,       1, 2, _S("[ZEN_GARDEN]") },

// 智慧树（附加页第 2 行第 4 列，图标 10）
{ GAMEMODE_TREE_OF_WISDOM,            10, CHALLENGE_PAGE_LIMBO,       2, 4, _S("[TREE_OF_WISDOM]") },

// 无尽生存第 3 关（泳池无尽）—— 注意此条被放在 SURVIVAL 页，其余无尽在 LIMBO 页
{ GAMEMODE_SURVIVAL_ENDLESS_STAGE_3,  10, CHALLENGE_PAGE_SURVIVAL,    2, 2, _S("[SURVIVAL_POOL_ENDLESS]") },
```

**数据亮点**：
- 无尽生存第 1/2/4/5 关位于 `CHALLENGE_PAGE_LIMBO`（第 3 行），第 3 关（泳池无尽）却在 `CHALLENGE_PAGE_SURVIVAL`——这是原版刻意设计（泳池无尽作为「无限生存」入口之一放到生存页）。
- 同一玩法有升级版时图标复用：`WAR_AND_PEAS` 与 `WAR_AND_PEAS_2` 同用图标 0，`WALLNUT_BOWLING` 与 `WALLNUT_BOWLING_2` 同用图标 6。
- `RESODDED`（无草皮之地）条目的名称键是 `[UNSODDED]`，存在枚举名与显示名不一致的历史遗留。

## 4. 辅助结构

### 4.1 ZombiePicker（`Board.h:151-157`）

僵尸波次填充过程中的「工作区」结构，`Board::PickZombieWaves()` 在栈上创建：

| 字段 | 类型 | 含义 |
|------|------|------|
| `mZombieCount` | `int` | 当前波已放入的僵尸数量（上限 `MAX_ZOMBIES_IN_WAVE=50`） |
| `mZombiePoints` | `int` | 当前波剩余的「僵尸点数」预算（每只僵尸消耗其 `mZombieValue`） |
| `mZombieTypeCount[]` | `int[NUM_ZOMBIE_TYPES]` | **当前波**每种僵尸的已出数量（每波清零） |
| `mAllWavesZombieTypeCount[]` | `int[NUM_ZOMBIE_TYPES]` | **整局累计**每种僵尸的已出数量（跨波保留，用于无尽模式红眼巨人总量控制） |

配套函数：
- `ZombiePickerInitForWave()`（`Board.cpp:540`）——清零整结构（每波开始调用）
- `ZombiePickerInit()`（`Board.cpp:546`）——额外清零 `mAllWavesZombieTypeCount`（整局开始调用）
- `Board::PutZombieInWave()`（`Board.cpp:553`）——把僵尸写入 `mZombiesInWave[wave][count]`，扣点数，累加计数
- `Board::PutInMissingZombies()`（`Board.cpp:567`）——冒险模式最终波补足本关所有可出场僵尸
- `Board::PickZombieType()`（`Board.cpp:2451`）——加权随机选一种僵尸（详见 §8）

### 4.2 ZombieAllowedLevels（`Challenge.h:252-257`）

| 字段 | 类型 | 含义 |
|------|------|------|
| `mZombieType` | `ZombieType` | 该条目描述的僵尸类型 |
| `mAllowedOnLevel[]` | `int[NUM_LEVELS]`（50） | 该僵尸在**冒险模式 1~50 关**各关卡是否允许出现（0/1） |

全局实例 `gZombieAllowedLevels[NUM_ZOMBIE_TYPES]`（`Challenge.cpp:37-255`，地址 `0x6A35B0`）。它是冒险模式「僵尸种类随关卡逐步解锁」的数据表，例如：
- `ZOMBIE_NORMAL` / `ZOMBIE_FLAG`：全部 50 关都为 1
- `ZOMBIE_TRAFFIC_CONE`：第 1、2 关为 0，第 3 关起为 1
- `ZOMBIE_DANCER`：仅第 18~20 关（3-2 到 3-4）为 1
- `ZOMBIE_GARGANTUAR`：仅第 48~50 关为 1
- 特殊僵尸（`ZOMBIE_BOSS`/`ZOMBIE_PEA_HEAD` 等 8 种）整表为 0（仅供特殊模式手动刷出）

配套全局量：
- `int gZombieWaves[NUM_LEVELS]`（`Challenge.cpp:29`，地址 `0x6A34E8`）——冒险模式每关**总波数**（4~30 不等，第 30 关达峰值 30）
- `SeedType gArtChallengeWallnut / SunFlower / StarFruit[6][9]`（`Challenge.cpp:257-282`）——三个「艺术画」挑战的目标图案（6 行 × 9 列的 `SEED_*` 位图，`SEED_NONE` 为空白格）

### 4.3 关于 StageProperty

> **注意**：本工程**不存在** `struct StageProperty`（已全工程 `grep` 验证无匹配）。原版/其他反编译分支中描述「生存模式各阶段属性」的结构在本工程中被 `Challenge::InitZombieWavesSurvival()` 内的**内联逻辑**替代（见 §8.2），无需独立结构。若后续需还原，可把 §8.2 中的筛选条件抽成结构体。

### 7.3 解锁规则要点（`MoreTrophiesNeeded`）

- **试用版锁定**：`IsTrialStageLocked()` 时解谜第 4 罐起、挑战页种子雨起、生存第 4 关起需额外奖杯。
- **解谜页**：砸罐子/我是僵尸按「已通关数」线性解锁；第 4 关起若未通关冒险则需额外条件。
- **生存/挑战页**：未通关冒险时前 3 格免费、第 4 格 1 奖杯、其余 2 奖杯；已通关后按该页奖杯总数线性解锁。
- **无尽生存**：需生存页 10 个奖杯全齐（或作弊旁路）。

## 8. 关键流程说明

### 8.1 波次生成总流程（三层协作）

```
Board::PickZombieWaves()  ── 决定 mNumWaves（总波数）
   ├─ Challenge::InitZombieWaves()  ── 设置 Board::mZombieAllowed[]（允许出场的僵尸白名单）
   └─ 每波循环：
        ├─ 计算本波 mZombiePoints（僵尸点数预算）
        ├─ 固定出怪（旗帜波、介绍僵尸、伽刚特尔、柱子关特殊波…）
        └─ while (点数>0)  Board::PickZombieType() → PutZombieInWave()
```

**总波数规则**（`Board.cpp:579-619`）：
- 冒险模式：`gZombieWaves[level-1]`（4~30）；二周目非 BOSS 关至少 20、否则 +10
- 生存 / 背水一战：`GetNumWavesPerSurvivalStage()`（每面旗帜的波数）
- 打僵尸 12 波；保龄球/空袭/墓地/高重力/传送门/战争与豌豆/隐形 20 波；暴风雨/小麻烦/蹦极/列队/铲子/战与豌 2/保龄球 2/跳跳 30 波；其余 40 波
- 禅境/智慧树/松鼠 0 波（无常规出怪）

**每波点数**（`Board.cpp:653-708`）：基础 `aWave/3+1`（冒险二周目 `aWave*2/5+1`；生存按阶段累计；背水一战另算），旗帜波 ×2.5；列队 ×6、小麻烦/保龄球 ×4、小 BOSS ×3、暴风雨冒险 ×3、铲子/蹦极/传送门/隐形 ×2。

### 8.2 生存模式随机出怪池（`InitZombieWavesSurvival`，`Challenge.cpp:2510`）

这是「生存无尽」的核心难度曲线：每进入新一面旗帜（`mSurvivalStage+1`）就扩充一次允许池。

1. 固定允许 `ZOMBIE_NORMAL`；5 选 1 出现 `ZOMBIE_NEWSPAPER`（读报）否则 `ZOMBIE_TRAFFIC_CONE`（路障）。
2. `aCapacity = min(mSurvivalStage+1, 9)`：每次最多新引入 9 种。
3. 循环随机抽取 `NUM_ZOMBIE_TYPES` 内类型，命中以下任一条件则**跳过**（`continue`）：
   - 已在允许列表
   - 仅泳池的僵尸（`IsZombieTypePoolOnly`）但关卡无泳池
   - 屋顶关禁止 `DIGGER`/`DANCER`；有墓碑禁止 `ZAMBONI`
   - 蹦极仅限屋顶生存或无尽
   - 前 10 面旗帜不出红眼巨人（`GetSurvivalFlagsCompleted()<10`）
   - 普通生存 1~3 关禁止 `> SNORKEL` 的后续僵尸
   - `IsZombieTypeSpawnedOnly`（只能被间接刷出的类型）
   - 僵尸植物（Zombotany）、鸭子救生圈、雪人
4. 通过筛选 → `mBoard->mZombieAllowed[aRandZombie] = true`，`aCapacity--`。

`InitZombieWaves()`（`Challenge.cpp:2595`）则对**非生存模式**逐一硬编码允许列表（如打僵尸仅普通/路障/铁桶；保龄球 2 加舞王+门板；战争与豌豆只出豌豆头/坚果头等），末尾 `CanSpawnYetis()` 时统一加雪人。

### 8.3 加权随机选僵尸（`Board::PickZombieType`，`Board.cpp:2451`）

1. 遍历 `NUM_ZOMBIE_TYPES`，过滤掉 `!mZombieAllowed` 的类型。
2. 出怪限制：蹦极在无尽仅旗帜波；`mFirstAllowedWave`（最早出场波）限制（无尽中随旗帜数前移）；剩余点数不足 `mZombieValue` 也排除。
3. 生存模式动态调权（`mPickWeight`）：
   - 伽刚特尔/雪橇车：每波数量上限随旗帜数 `2→50` 递增
   - 红眼巨人：旗帜波每波上限 1→50、非旗帜波全局限 1→50（且非旗波权重拔高到 1000）
   - 普通僵尸/路障：权重随旗帜数衰减（普通 ÷10、路障 ÷4）
4. `TodPickFromWeightedArray` 加权随机返回一种。

**关键数据**：每种僵尸的 `mZombieValue`（点数消耗）、`mPickWeight`（基础权重）、`mFirstAllowedWave`（最早波）定义于 `gZombieDefs[]`（`Zombie.cpp`）。

### 8.4 传送带发种（`UpdateConveyorBelt`，`Challenge.cpp:1630`）

- 发种间隔 `mConveyorBeltCounter`：按场上已有种子数分档（>8 时 1000、>6 时 500、>4 时 425、否则 400），再乘模式速度系数（最终决战 0.875 / 铲子与传送门 1.5 / 隐形 2.0 / 列队 3.0）。
- 每关/模式各有一张**加权种子表**（如最终决战：花盆 55 + 西瓜投手 10 + 辣椒 12 + 卷心菜 10 + 玉米 5 + 冰蘑菇 8）。
- 动态调权：墓碑清理者多于墓碑数→0；睡莲/花盆按场上数衰减；同种子在传送带 ≥4 个→权重 1；连续同种减半。
- 选出的种子 `mBoard->mSeedBank->AddSeed()`，并记 `mLastConveyorSeedType` 防连续重复。

### 8.5 我是僵尸关卡阵型（`IZombieInitLevel`，`Challenge.cpp:4581`）

- 先铺 5 个 `GRIDITEM_IZOMBIE_BRAIN`（每行一个，位于第 0 列左侧）。
- 1~9 关：`IZombiePlacePlantInSquare`（固定格）+ `IZombiePlacePlants`（加权随机在红线左侧）组合摆出向日葵/豌豆/雪豆/土豆雷/火炬/坚果/大蒜/大嘴花/仙人掌/磁力菇等阵型。
- 无尽：按 `mSurvivalStage` 动态生成——向日葵 + 小喷菇数量随阶段变化，再随机选「输出/爆炸/倾斜/穿刺/回复」或「综合/控制/即死」阵型。
- 植物可种列数（`IZombiePlacePlants` / `CanPlantAt`）：1~5 关 4 列、6~8 关与无尽 5 列、9 关 5 列（特例）、其余 6 列——红线位置随关卡右移。
- 胜利条件：吃掉 5 个脑子（`mChallengeScore==I_ZOMBIE_WINNING_SCORE`）；无尽模式则进入下一解谜阶段。

### 8.6 打僵尸波次（`WhackAZombieSpawning`，`Challenge.cpp:2842`）

与常规出怪完全不同：僵尸**从墓碑钻出**而非从右进场。

1. 每波 `mZombieCountDown` 从 2000 递减；倒计时 100 时补墓碑（保持 5 块）、5 时 `NextWaveComing()`。
2. 状态计数归零时刷怪：`aPhase = clamp((wave-1)*6/12, 0, 5)`（12 波分成 6 个难度阶段）。
3. 数量/类型概率表：
   - 双连概率 `{0,30,10,10,15,18}`、三连概率 `{0,0,0,0,10,13}`、铁桶 `{0,0,0,10,15,15}`、路障 `{0,0,30,30,30,30}`。
   - 默认 1 只普通僵尸；末波固定 20 只（铁桶/路障随机，速度 2）。
4. 从**有墓碑且非墓碑吞噬者占用的格子**中加权随机选格，`RiseFromGrave` 钻出，速度 `RandRangeFloat(0.5, aMaxSpeed)`（`aMaxSpeed` 随波数 1→3 缓入）。
5. 刷怪间隔 `100→30`（最小）/ `200→60`（最大）随波数线性缩短。

### 8.7 传送门瞬移（`UpdatePortal`，`Challenge.cpp:3234`）

对每种「可穿门对象」检测是否到达门中心（误差 20~45px），命中则移到配对门位置并改行：

- **僵尸**：`mLastPortalX` 防同门重复触发，`SetRow` 换行。
- **子弹**：仅 `MOTION_STRAIGHT`，按门行差补偿 `mY/mShadowY`，重算渲染层。
- **割草机**：仅 `MOWER_TRIGGERED` 态，换行后 `Update()`。
- `CanTargetZombieWithPortals`：沿传送链最多 3 跳判断植物能否打到僵尸（用于植物索敌）。
- `PortalCombatRowSpawnWeight`：门所在行权重 1.0、无门行 0.2、离割草机 <5 格 0.01（控制刷怪位置）。

### 8.8 宝石迷阵核心（Beghouled）

- **无解检测**：`BeghouledCheckStuckState` 定时把棋盘转快照 → `BeghouledCheckForPossibleMoves` 穷举所有邻格交换（旋转模式穷举所有 2×2 旋转）看是否产生三连；无解则提示并等待洗牌。
- **下落**：`BeghouledRemoveMatches` 消三连 → `BeghouledMakePlantsFall` 从顶向下补空 → 递归检测新三连（连消）。
- **计分**：`BeghouledScore` 每消一个加 1 分，累计 75 分胜利；玩家被吃格子累计解锁「清弹坑」按钮。
- **升级**：花阳光购买后 `BeghouledPacketClicked` 把场上所有基础植物替换为升级版（豌豆→双重射手等，每个升级仅一次）。

### 9.1 ★★★ 高度可复用（通用算法，解耦后可独立成库）

| 组件 | 位置 | 复用价值 |

| **波次程序化生成**：`InitZombieWavesSurvival` + `Board::PickZombieType` + `PickZombieWaves` | `Challenge.cpp:2510` / `Board.cpp:579,2454` | 点数预算 + 加权随机 + 上限曲线 + 白名单过滤的「关卡出怪系统」是塔防/求生类玩法的标准范式，可直接移植到自研引擎 |
| **加权随机选择**：`TodPickFromWeightedArray` / `TodPickFromWeightedGridArray` 的大量使用 | 贯穿全文件 | 所有「按权重抽一项」的底层工具，普适 |

| **种植合法性**：`CanPlantAt` | `Challenge.cpp:2457` | 「区域/红线/图案约束」的放置规则中枢，结构清晰 |

### 9.2 ★★ 中等复用（结构清晰但绑定 PvZ 语义）

- `InitZombieWaves()`（模式→僵尸白名单映射，数据驱动风格好，但枚举值绑定 PvZ）
- `ScaryPotterPopulate()` / `ScaryPotterPlacePot()`（铺罐数据表 + 加权放罐，可借鉴「关卡布局描述表」思路）
- `IZombieInitLevel()`（预设阵型数据表，可借鉴「关卡摆图」声明式描述）
- `WhackAZombieSpawning()`（分阶段难度曲线 + 概率表，可借鉴「难度递增」结构）
- `SpawnZombieWave()` / `UpdateZombieSpawning()`（出波钩子/接管机制）
- `PuzzleNextStageClear()` / `PuzzlePhaseComplete()`（无尽解谜阶段推进框架）

### 9.3 ★ 低复用（纯 PvZ 表现层）

- 所有 `Draw*` 系列（雨、暴风雨、老虎机、艺术画、智慧树）、`TreeOfWisdom*`、`Zombiquarium*`、`Squirrel*`、天气粒子、音效与提示文案——与 PvZ 资源/UI 强耦合。

### 9.4 移植建议

1. **波次系统**若独立抽取：需一并带走 `ZombieDefinition`（`mZombieValue`/`mPickWeight`/`mFirstAllowedWave`）、`TodAnimateCurve`（曲线插值）、`TodWeightedArray` 三件套；`Challenge` 里的白名单逻辑与 `Board` 里的点数预算逻辑本是两处，建议合并为单一 `WaveScheduler` 类。
2. **三消算法**几乎无外部依赖（只依赖 8×5 的 `SeedType` 二维数组），可直接抽成 `Match3Board` 类。
3. 本文件大量用 `TOD_ASSERT` 与全局 `gSexyAppBase`，移植时需替换为注入式上下文（`mApp` 已是成员，可顺势改为构造注入）。
