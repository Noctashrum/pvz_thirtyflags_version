## 1. 模块职责

本模块覆盖了《植物大战僵尸》(PvZ) 反编译工程中「资源加载 / 音乐播放 / 游戏存档 / 玩家档案」四大基础系统，以及两个跨平台/工具类组件：

| 文件 | 职责 | 关键点 |
|---|---|---|
| `Resources.h/.cpp` | 全资源 ID 枚举 + 全局资源指针 + PAK 资源抽取函数 + ID↔指针互查 | 单一巨大 `ResourceId` 枚举，628 项资源 |
| `Music.h/.cpp` | BASS 驱动的音乐状态机：主旋律/鼓点/踩镲三条音轨的同步、Burst（大波僵尸）淡入淡出 | MO3 模块音乐，多轨静音切换 |
| `SaveGame.h/.cpp` | 游戏进行中存档（Board 全量二进制快照）读写 | 原始字节流 + 魔术数/版本/编译日期校验 |
| `DataSync.h/.cpp` | 跨平台数据同步抽象层：Reader/Writer/Sync 模板，指针表序列化 | 存档/档案的底层序列化引擎 |
| `PlayerInfo.h/.cpp` | 单个玩家档案：等级/金钱/进度/盆栽 | user%d.dat，版本 12 |
| `ProfileMgr.h/.cpp` | 多用户档案管理（增删改查、按使用顺序淘汰） | users.dat，版本 14 |
| `PopDRMComm.h/.cpp` | PopCap DRM 正版校验通信（Windows 消息 + 共享内存） | 全部被 `_ENABLE_DRM_FOR_DEBUGGING` 包裹，正常构建为空壳 |
| `TypingCheck.h/.cpp` | 作弊码输入检测（滑动窗口子串匹配） | 与 LawnApp 的作弊系统联动 |

## 2. Resources 分析（枚举清单 + 规模）

### 2.1 结构总览（重要结论：不是分散枚举，而是**单一巨大枚举 + 逐一 extern 全局变量**）

`Resources.h`（1325 行，85KB）整体被 `namespace Sexy` 包裹（第 6 行开，第 1321 行闭）。内部只有 **1 个 enum**：

```cpp
// Resources.h:12-643
namespace Sexy {
    enum ResourceId {
        IMAGE_BLANK_ID,              // 0
        ...
        RESOURCE_ID_MAX              // 628（哨兵，非真实资源）
    };
    ...
}
```

后面（644-1274 行）是**逐一 `extern` 的全局变量声明**，每个都带内存地址注释（反编译时从二进制确定的 BSS 地址）：

```cpp
extern int    SOUND_SHIELDHIT;          //0x6A71A0
extern Image* IMAGE_TROPHY_HI_RES;      //0x6A71A8
extern Font*  FONT_BRIANNETOD16;        //0x6A7224
```

对应实现见 `Resources.cpp`：先逐一定义这些全局变量（默认 nullptr/0），再由 `Extract*` 函数从 PAK 中加载填充，最后用一个 628 项的 `gResources[]` 指针数组把「枚举 ID → 全局变量地址」串起来。

### 2.2 枚举项规模统计

| 前缀 | 数量 | 说明 |
|---|---|---|
| `IMAGE_*_ID` | **440** | 图像资源（精灵、UI、背景、Reanim 动画帧） |
| `FONT_*_ID` | **21** | 字体（含 1 个 `FONT_IMAGE_HOUSEOFTERROR28_ID`，实际是 Image* 类型） |

| 类型 | 数量 |

### 3.4 循环 / 淡入淡出逻辑（重点）

**循环**：`PlayFromOffset` 中 `BASS_ChannelSetFlags(..., BASS_MUSIC_LOOP)` 令 MO3 音乐循环；MV（`MUSIC_FILE_CREDITS_ZOMBIES_ON_YOUR_LAWN`，ogg 流）设为 `aNoLoop=true` 不循环。

**淡入淡出（Burst 大波僵尸）**：`UpdateMusicBurst` 是核心状态机，用 `TodAnimateCurveFloat(时长, 0, 剩余计数, 起始, 终止, CURVE_LINEAR)` 做线性插值：

- `MUSIC_BURST_OFF`：屏上僵尸 ≥10（或 `mBurstOverride==1`）→ `StartBurst()`。
- `MUSIC_BURST_STARTING`：
  - 方案1（白天/泳池/雾/屋顶）：踩镲 `aFadeTrackVolume` 0→1 淡入（400 帧），计数到 100 时把鼓点置 `DRUMS_ON_QUEUED`（等待下个乐句起鼓）；计数到 0 → `ON`（持续 800 帧）。
  - 方案2（黑夜）：主旋律 1→0 淡出、鼓点起。
- `MUSIC_BURST_ON`：踩镲音量恒 1；屏上僵尸 <4（或 override==2）→ 进入 `FINISHING`。
- `MUSIC_BURST_FINISHING`：踩镲 1→0 淡出（800 帧）/ 主旋律 0→1 恢复（黑夜 400 帧），鼓点 `FADING` 渐弱后归 `OFF`。

**鼓点状态机**：`ON_QUEUED` 时等 `aOrderMain != aOrderDrum`（即跨过一个乐句边界）才真正开鼓，避免节奏错位；`OFF_QUEUED` 同理延迟到乐句边界关鼓。黑夜方案还用 `BASS_ChannelSetPosition` 做鼓点「跳乐句」（76/77 号乐句交替）实现节奏变化。

**暂停**：`GameMusicPause(true)` 记录 `mPauseOffset = MAKELONG(LOWORD(order), HIWORD(order)/4)` 后停轨；恢复时 `PlayMusic(cur, mPauseOffset, mPauseOffsetDrums)` 从偏移重播。

## 4. SaveGame 分析（含二进制格式详解）

> **注意区分两套存档体系**：
> 1. **本节的 `SaveGame.cpp` = 游戏进行中存档**（`gameN_*.dat`，Board 全量快照），用 **`Sexy::Buffer` 位级缓冲 + 原始字节流**，不用 DataSync。
> 2. **第 5 节的 PlayerInfo/ProfileMgr = 玩家档案**（`users.dat`/`user%d.dat`），用 **DataSync**（含 `SyncSummary` 版本校验）。任务中提到的「SyncSummary 校验」属于档案体系，不是本节的 SaveGame。

### 4.1 文件头 `SaveFileHeader`（12 字节）

```cpp
struct SaveFileHeader {
    unsigned int mMagicNumber;   // 0xFEEDDEAD
    unsigned int mBuildVersion;  // 2
    unsigned int mBuildDate;     // crc32(__DATE__ __TIME__) —— 编译时间戳的 CRC32
};
```

三常量（SaveGame.cpp:15-18）：
```cpp
SAVE_FILE_MAGIC_NUMBER = 0xFEEDDEAD
SAVE_FILE_VERSION      = 2U
SAVE_FILE_DATE         = crc32(0, (Bytef*)__DATE__ __TIME__, strlen(...))
```

### 4.2 版本号处理

`LawnLoadGame`（506 行）加载时三重校验，任一不匹配直接返回 false（拒绝读档）：
```cpp
aContext.SyncBytes(&aHeader, sizeof(aHeader));
if (aHeader.mMagicNumber != SAVE_FILE_MAGIC_NUMBER ||
    aHeader.mBuildVersion != SAVE_FILE_VERSION ||
    aHeader.mBuildDate   != SAVE_FILE_DATE) return false;
```

`mBuildDate = CRC32(编译时间字符串)` 意味着：**换一次编译环境/日期，旧存档全部失效**——这是反编译工程特有的脆弱点（原版用固定的游戏版本号）。若要跨构建兼容，需把 `mBuildDate` 改为固定常量。

### 4.3 序列化机制：`SaveGameContext`（位级 Buffer + 长度前缀）

```cpp
class SaveGameContext {
    Sexy::Buffer mBuffer;   // 位级精度缓冲（mDataBitSize/mReadBitPos）
    bool mFailed;           // 读失败标记
    bool mReading;          // 读/写方向
};
```

- `ByteLeftToRead()`：`(mDataBitSize - mReadBitPos + 7) / 8` 剩余字节数。
- `SyncBytes(dest, size)`：**带长度前缀**。写时先 `WriteLong(size)` 再 `WriteBytes`；读时先 `ReadLong()` 取长度并校验 `== size` 且剩余字节足够，否则 `mFailed=true` 并清零 dest。这是防篡改/防截断的关键。
- `SyncInt`：直接 4 字节 `ReadLong/WriteLong`（无前缀），读前检查剩余 ≥4 字节。
- `SyncUint`：转 `SyncInt`。
- `SyncReanimationDef` / `SyncParticleDef` / `SyncTrailDef`：把**对象指针**序列化为**枚举索引**（写：遍历全局 def 数组找索引；读：按索引从 `gReanimatorDefArray`/`gParticleDefArray`/`gTrailDefArray` 还原指针），越界即 `mFailed`。
- `SyncImage`：把 `Image*` 序列化为 `ResourceId`（写用 `GetIdByImage`，读用 `GetImageById`），空指针用 `RESOURCE_ID_MAX` 表示。

## 5. DataSync / PlayerInfo / ProfileMgr / PopDRMComm / TypingCheck 分析

### 5.1 DataSync（跨平台数据同步抽象，639 行）

三层结构，职责清晰、通用性极强：

**`DataReader`（12 个函数）**：文件/内存双源读取。`OpenFile`/`OpenMemory(data,len,takeOwnership)`/`Close`/`Rewind`，逐项读取 `ReadLong/ReadShort/ReadByte/ReadBool/ReadFloat/ReadDouble/ReadString`。`ReadBytes` 越界抛 `DataReaderException`。`ReadString` 格式 = `ReadShort()` 长度 + 字符串字节。

**`DataWriter`（12 个函数）**：文件/内存双目标写入。`EnsureCapacity`（容量翻倍扩容）、`OpenMemory(reserve=32)`、`WriteLong/WriteShort/WriteByte/WriteBool/WriteFloat/WriteDouble/WriteString`（`WriteString` = 2 字节长度 + 字节）。

**`DataSync`（核心）**：读写合一的双向同步器，构造时绑定 Reader 或 Writer。提供海量重载：
- `SyncLong`/`SyncSLong`（4 字节，无/有符号）、`SyncShort`/`SyncSShort`（2 字节）、`SyncByte`/`SyncSByte`（1 字节）——每种 7 个重载（char/short/long/unsigned char/unsigned short/unsigned long/int）。
- `SyncBool`/`SyncFloat`/`SyncDouble`/`SyncString`/`SyncBytes`。
- `SetVersion`/`GetVersion`：版本号支持（由调用方决定是否继续）。
- **指针表机制**：`mPointerToIntMap`/`mIntToPointerMap`/`mPointerSyncList`/`mCurPointerIndex`，`SyncPointers`/`SyncPointer`/`RegisterPointer` 用于把指针序列化为稳定整数 ID（`nullptr` 恒为 0）。本项目存档基本用不到，但这是完整的指针图序列化方案。

> 可复用性：**DataSync 是整个工程通用性最高的组件**（★★★），几乎不依赖 Lawn 类型，可整体迁移做「双向读写的字节流序列化器」。

关键成员：`DataReader* mReader` / `DataWriter* mWriter` / `int mVersion` / `PointerToIntMap mPointerToIntMap` / `IntToPointerMap mIntToPointerMap` / `vector<void**> mPointerSyncList` / `int mCurPointerIndex`。

### 5.5 TypingCheck（作弊码输入检测，57 行）

**极简而通用的小工具**（★★★）。滑动窗口子串匹配：

```cpp
class TypingCheck {
    std::string mPhrase;        // 目标短语（已转成 KeyCode 序列）
    std::string mRecentTyping;  // 最近按键序列
};
```

- `SetPhrase(str)`：逐字符 `AddChar`（转小写→`GetKeyCodeFromName` 映射成 KeyCode）拼到 `mPhrase`。
- `AddKeyCode(KeyCode)`：直接追加一个 KeyCode（用于方向键等非字母键，如 Konami 码）。
- `AddChar(char)`：转小写后按字符名查 KeyCode。
- `Check()`：`mRecentTyping == mPhrase` 即命中，命中后清空 `mRecentTyping`。
- `Check(KeyCode)`：追加按键 → 若超长则截尾（保留最后 `mPhrase.size()` 个）→ 调用 `Check()`。

**与 LawnApp 作弊系统联动**：
- `LawnApp` 持有 10 个 `TypingCheck*`（mKonamiCheck/mMustacheCheck/mMoustacheCheck/mSuperMowerCheck/mSuperMowerCheck2/mFutureCheck/mPinataCheck/mDanceCheck/mDaisyCheck/mSukhbirCheck），构造时用 `AddKeyCode`/`AddChar` 配置短语（1666-1685 行）。
- Konami 码 = `↑↑↓↓←→←→ba`（1667-1676 行，方向键用 AddKeyCode，b/a 用 AddChar）。
- 命中后置 `mPlayerInfo->mHasUsedCheatKeys = 1`（LawnApp.cpp:1920-1922），并进入相应作弊模式（胡子/超能割草机/未来/皮纳塔/跳舞/雏菊/Sukhbir）。
- 作弊键总开关 `mTodCheatKeys` 由 `-tod` 命令行参数打开（仅 DEBUG，1728-1733 行）。
- 分发点：`Board::DoTypingCheck`（Board.cpp:7775）、`SeedChooserScreen`、`LawnDialog`、`NewOptionsDialog`、`GameSelector` 等多处按键入口。

## 6. 关键流程说明

### 6.1 资源加载流程
1. 启动：`ResourceManager` 打开 PAK → 按需调用 `ExtractResourcesByName` 分派到 `ExtractInit/LoaderBar/LoadingFonts/LoadingImages/LoadingSounds` 等。
2. 每个 `Extract*` 先置 `gNeedRecalcVariableToIdMap=true`，再 `GetImageThrow/GetFontThrow/GetSoundThrow` 填充全局变量，异常 `ResourceManagerException` 则返回 false。
3. 延迟加载：进入特定界面（图鉴/商店/各背景/僵尸便签等）时再调用对应 `ExtractDelayLoad_*`。
4. 运行时查资源：`GetImageById(id)` 等；反向由 `GetIdByVariable` 惰性构建 `map` 反查。

### 6.2 音乐播放流程
1. `MusicInit` 加载 `mainmusic.mo3`（主+鼓）与 `mainmusic_hihats.mo3`（踩镲）。
2. `StartGameMusic` 依据关卡阶段选 `MusicTune` → `MakeSureMusicIsPlaying` → `PlayMusic`。
3. `PlayMusic` 按曲目决定轨道组合与起始乐句偏移，`PlayFromOffset` 设各轨音量（主=100%，鼓/踩镲=0%）。
4. 每帧 `MusicUpdate` → `UpdateMusicBurst`（大波僵尸淡入踩镲/鼓点）+ `MusicResync`（鼓/踩镲向主旋律对齐 BPM）。
5. `GameMusicPause` 暂停/恢复。

### 6.3 游戏存档流程
1. 存：`LawnSaveGame` → 写 `SaveFileHeader` → `SyncBoard`（Board 内存快照 + 各 DataArray + 子系统对象 + 尾部魔术数）→ `WriteBufferToFile`。
2. 读：`LawnLoadGame` → `ReadBufferFromFile` → 校验头部三字段 → `SyncBoard` → 校验尾部魔术数 → `FixBoardAfterLoad` 重挂指针 → 切到 SCENE_PLAYING。
3. 任何字段长度/魔术数/版本/日期不符即 `mFailed=true` 拒绝。

### 6.4 档案读写流程
1. `ProfileMgr::Load` 读 `users.dat`（版本 14 + 档案列表摘要）。
2. 选中玩家时 `GetProfile/GetAnyProfile` → `PlayerInfo::LoadDetails` 读 `user%d.dat`（版本 12 全量字段）。
3. `SyncSummary` 只用于 users.dat 列表（名字/useSeq/id），`SyncDetails` 用于 user%d.dat 全量。

### 7.1 特别提示（对二次开发）

1. **存档 `mBuildDate` 陷阱**：`SaveGame.cpp` 用 `crc32(__DATE__ __TIME__)` 做版本校验，任何重编译都会令旧存档失效。若要保留存档兼容性，改 `SAVE_FILE_DATE` 为固定值。
2. **两套版本号**：游戏存档版本=2（SaveGame.cpp），用户档案版本=12（PlayerInfo.cpp），档案列表版本=14（ProfileMgr.cpp），三者独立，升级格式时分别处理。
3. **`SyncDetails` 的 `SyncBytes(&mPottedPlant[i], sizeof(PottedPlant))`**：直接按结构体尺寸序列化，存在结构体内存布局/对齐跨平台风险（`__time64_t` 等），与 DataSync 的跨平台初衷相悖，实际是「近似跨平台」。
4. **`gNeedRecalcVariableToIdMap`**：加载/卸载资源后必须置 true，否则 `GetIdByImage` 反查会返回过期 ID（存档里 `SyncImage` 依赖反查的正确性）。
