# 僵尸系统模块文档
> 所属: src/Lawn | 文件: Zombie.h / Zombie.cpp

## 1. 模块职责

`Zombie.h` / `Zombie.cpp` 是《植物大战僵尸》反编译工程中体量最大、逻辑最密集的核心模块，负责游戏中**所有僵尸**的完整生命周期：

- 定义僵尸数据表 schema（`ZombieDefinition`）与全局数据表 `gZombieDefs`（33 条），以及 `ZombieType`、`ZombiePhase` 等十余个枚举。
- 实现 `Zombie` 类（继承自 `GameObject`），承载约 90 个成员变量与约 227 个成员函数，覆盖僵尸的初始化、移动、攻击/啃食、受伤、死亡、掉落、渲染、音效、以及每一种特殊僵尸（舞王/巨人/矿工/蹦极/投石车/雪橇/海豚/潜水/气球/跳跳/僵尸博士 Boss 等）的专属状态机逻辑。

## 2. ZombieDefinition 数据表结构（字段含义表）

定义位于 `Zombie.h:590-600`：

```cpp
class ZombieDefinition
{
public:
    ZombieType          mZombieType;        // 僵尸类型
    ReanimationType     mReanimationType;   // 动画资源类型 (REANIM_XXX)
    int                 mZombieValue;       // 击杀掉落价值
    int                 mStartingLevel;     // 起始出现关卡
    int                 mFirstAllowedWave;  // 首次允许出现的波次
    int                 mPickWeight;        // 随机选取权重
    const SexyChar*     mZombieName;        // 名称文本键
};
```

| 字段名 | 类型 | 含义 |
|--------|------|------|
| `mZombieType` | `ZombieType` | 该条目对应的僵尸类型枚举值；数据表按此索引，`GetZombieDefinition` 会断言 `gZombieDefs[t].mZombieType == t`。 |
| `mReanimationType` | `ReanimationType` | 僵尸身体使用的 Reanimation 动画资源 ID（如 `REANIM_ZOMBIE`、`REANIM_GARGANTUAR`、`REANIM_BOSS`）。`ZombieInitialize` 据此调用 `LoadReanim`。 |
| `mZombieValue` | `int` | 击杀后掉落的**基础价值**（金币当量）。`DropLoot()` 读取该值交给 `Board::DropLootPiece` 换算成实际金币/银币掉落；数值越大掉落越丰厚。 |
| `mStartingLevel` | `int` | 该僵尸**首次出场**的关卡号（1 表示第 1 关就出现）。特殊值 `99` 表示"非正常波次出场"的僵尸（僵尸头 ZOMBOTANY 系列），它们不参与常规关卡波次生成。 |
| `mFirstAllowedWave` | `int` | 允许在**第几波**开始出现（生成逻辑据此过滤）。 |
| `mPickWeight` | `int` | 波次随机挑僵尸时的**权重**；权重越高越容易被选。`0` 表示不参与随机挑选（如旗帜僵尸、伴舞、小鬼、Boss 等由特定逻辑生成）。 |
| `mZombieName` | `const SexyChar*` | 图鉴 / 文本系统中对应的本地化字符串键（`_S("ZOMBIE")` 等），用于 Almanac 显示与名称查找。 |

### 3.4 示例条目解析

**① 普通僵尸（索引 0）**
```
{ ZOMBIE_NORMAL, REANIM_ZOMBIE, 1, 1, 1, 4000, _S("ZOMBIE") }
```
- 用最普通的 `REANIM_ZOMBIE` 动画；价值 1（最低档）；第 1 关、第 1 波即出现；权重 4000（最高档，最常见）。初始化时仅 `LoadPlainZombieReanim()`，`mBodyHealth=270`。

**② 路障僵尸（索引 2）**
```
{ ZOMBIE_TRAFFIC_CONE, REANIM_ZOMBIE, 2, 3, 1, 4000, _S("CONEHEAD_ZOMBIE") }
```
- 同样用普通僵尸动画，但在 `ZombieInitialize` 中 `ReanimShowPrefix("anim_cone", ...)` 显示路障、隐藏头发，设置 `mHelmType = HELMTYPE_TRAFFIC_CONE`、`mHelmHealth = 370`。价值 2，第 3 关出现，权重 4000。

**③ 铁桶僵尸（索引 4）**
```
{ ZOMBIE_PAIL, REANIM_ZOMBIE, 4, 8, 1, 3000, _S("BUCKETHEAD_ZOMBIE") }
```
- 铁桶帽 `mHelmType = HELMTYPE_PAIL`、`mHelmHealth = 1100`；价值 4，第 8 关出现。

**④ 巨人僵尸（索引 23）**
```
{ ZOMBIE_GARGANTUAR, REANIM_GARGANTUAR, 10, 48, 15, 1500, _S("GARGANTUAR") }
```
- 独立 `REANIM_GARGANTUAR` 动画；价值 10（最高档）；第 48 关、第 15 波出现；初始化时 `mBodyHealth=3000`、`mWidth/mHeight=180`、攻击/受击矩形放大，并随机电杆皮肤（普通/鸭子/电话杆）。红眼巨人为索引 32，`mBodyHealth=6000`、权重 6000。

**⑤ 僵尸博士 Boss（索引 25）**
```
{ ZOMBIE_BOSS, REANIM_BOSS, 10, 50, 1, 0, _S("BOSS") }
```
- 最终 Boss；权重 0（仅由剧情/关卡触发）；初始化时 `mBodyHealth = 冒险模式 40000 / 其它 60000`，挂 `RENDER_LAYER_TOP`，`mZombieRect=Rect(700,80,90,430)`，进入 `PHASE_BOSS_ENTER`。

## 8. 关键流程说明

### 8.1 僵尸状态机（mZombiePhase）

- **主状态**：`PHASE_ZOMBIE_NORMAL`（正常）→ 受伤/死亡进入 `PHASE_ZOMBIE_DYING`（濒死，播死亡动画）→ 之后由 `UpdateDeath` 在动画循环结束后设置 `mZombieFade`，淡出后 `DieNoLoot`；`PHASE_ZOMBIE_BURNED`（燃烧，`ApplyBurn`→`UpdateBurn`）与 `PHASE_ZOMBIE_MOWERED`（被割草机碾压，`MowDown`→`UpdateMowered`）是两条"无尸体"的特殊死亡通道。
- **调度**（`Zombie::Update` → `UpdatePlaying`）：`PHASE_RISING_FROM_GRAVE` 单独短路；否则按 `IsImmobilizied` 决定是否执行 `UpdateActions`（按 `mZombieType` 分发到各 `UpdateXxx` 特殊逻辑）→ `UpdateZombiePosition`（移动+碾压+吹飞）→ `CheckIfPreyCaught`（啃食判定）→ `CheckForPool/CheckForHighGround/CheckForBoardEdge`。
- **`ZombiePhase` 全集约 90 个**，按僵尸分组：`PHASE_BUNGEE_*`、`PHASE_POLEVAULTER_*`、`PHASE_JACK_IN_THE_BOX_*`、`PHASE_BOBSLED_*`、`PHASE_POGO_*`、`PHASE_NEWSPAPER_*`、`PHASE_DIGGER_*`、`PHASE_DANCER_*`、`PHASE_DOLPHIN_*`、`PHASE_SNORKEL_*`、`PHASE_ZOMBIQUARIUM_*`、`PHASE_CATAPULT_*`、`PHASE_GARGANTUAR_*`、`PHASE_IMP_*`、`PHASE_BALLOON_*`、`PHASE_LADDER_*`、`PHASE_BOSS_*`、`PHASE_YETI_RUNNING`、`PHASE_SQUASH_*` 等（完整枚举见第 4 节及 `Zombie.h:71-169`）。

### 8.2 移动与啃食（ZombieEat）

- **移动**：`UpdateZombieWalking` 优先取身体 Reanimation 的 `_ground` 轨道速度（`GetTrackVelocity`），否则用 `mVelX`；寒冰时速度 ×`CHILLED_SPEED_FACTOR(0.4)`。反向行走（`IsWalkingBackwards`，即被魅惑）时 `mPosX +=`。冰车/投石车每次步进调用 `CheckForZombieStep`→`CheckSquish(DRIVE_OVER)` 碾压植物。
- **啃食**（`CheckIfPreyCaught`）：每 `TICKS_BETWEEN_EATS(4)` tick 尝试一次（寒冰翻倍间隔）。优先级：`FindZombieTarget`（魅惑对攻）→ `FindPlantTarget(CHEW)` → IZ 模式啃大脑；都没有则 `StopEating`。`EatPlant` 每次减 `DAMAGE_PER_EAT(4)` 血，处理梯子（改爬梯）、爆炸/一次性植物的触发（`DoSpecial`）、植物死亡结算（`mPlantsEaten++`、`ZombieAtePlant` 回调）等。

### 8.3 伤害管线（TakeDamage）

`TakeDamage` 按"飞行器 → 护盾 → 头盔 → 身体"顺序结算：

1. `IsFlying()` 时先 `TakeFlyingDamage`（打气球）。
2. 剩余伤害且有护盾且非 `DAMAGE_BYPASSES_SHIELD` → `TakeShieldDamage`；若带 `DAMAGE_HITS_SHIELD_AND_BODY` 则重置剩余伤害为全额（同时穿透）。
3. 剩余伤害且有头盔 → `TakeHelmDamage`。
4. 仍剩余 → `TakeBodyDamage`：减血、按 `GetBodyDamageIndex` 切换损伤贴图（冰车/投石车/巨人/Boss 各有分支），血量 ≤0 时 `PlayDeathAnim` + `DropLoot`。

`DamageFlags` 位控制穿透/冻结/闪白/留尸/尖刺等行为；`EffectedByDamage` 供辣椒/冰菇/炸弹等范围伤害判断是否命中。

### 8.4 死亡（ZombieDie / DieNoLoot）与掉落物

- `DieNoLoot`：停止音效→销毁附着特效与身体/碾压/特殊头动画→`mDead=true`→`TrySpawnLevelAward`→按类型触发 `BobsledDie`/`BungeeDie`/`BossDie` 连带死亡。
- `DieWithLoot` = `DieNoLoot` + `DropLoot`。
- `DropLoot`：`AlmanacPlayerDefeatedZombie` 记录图鉴→雪人特判（4 颗钻石 + `mKilledYeti=true`）→`TrySpawnLevelAward`→`mBoard->DropLootPiece` 按 `mZombieValue` 掉落金币；僵尸水族馆与 IZ 模式不掉落。
- `TrySpawnLevelAward`：判定关卡是否应结束（最终 Boss/连续挑战/波次清空等），设置 `BOARDRESULT_WON` 并按关卡/模式生成奖励（便签/铲子/图鉴/车钥匙/玉米卷/浇水壶/银向日葵/金奖杯/钱袋等）。

## 9. 可复用性评估

### 高可复用（★★★，通用、低耦合）

- `GetZombieDefinition` + `gZombieDefs` 数据表：数据驱动，改数值即可调平衡，任何"新增僵尸"扩展的天然挂载点。
- `TakeDamage` / `TakeBodyDamage` / `TakeHelmDamage` / `TakeShieldDamage` / `TakeFlyingDamage`：分层伤害管线，逻辑清晰、可移植到其它单位系统。
- `DieNoLoot` / `DieWithLoot` / `DropLoot` / `TrySpawnLevelAward`：死亡-掉落-奖励的通用骨架。
- `GetZombieRect` / `GetZombieAttackRect` / `GetDrawPos` / `GetPosYBasedOnRow`：坐标与碰撞换算，可复用。
- `IsImmobilizied` / `CanBeChilled` / `CanBeFrozen` / `IsFireResistant` / `EffectedByDamage` / `IsDeadOrDying` / `IsFlying` / `IsOnBoard` / `IsWalkingBackwards`：纯状态查询，无副作用。
- `ReanimShowPrefix` / `ReanimShowTrack` / `PlayZombieReanim` / `SetAnimRate` / `ApplyAnimRate`：动画控制封装，可迁移。

### 中可复用（★★，需轻度改造）

- `EatPlant` / `CheckIfPreyCaught` / `FindPlantTarget` / `FindZombieTarget` / `CanTargetPlant`：啃食与目标选择，但强依赖 `Board`/`Plant`/`SeedType`。
- 各 `UpdateXxx` 特殊僵尸状态机：结构清晰（switch on `mZombiePhase`），可作新增特殊单位的模板，但每个都与本作美术资源/关卡规则耦合。
- `ZombieInitialize` 的类型 switch：装配逻辑集中，适合作为"新增类型"的参考实现，但直接复用需拆解。

### 低可复用（★，强耦合本作）

- 具体绘制函数（`DrawBungeeCord`/`DrawDancerReanim`/`DrawBossPart` 等）：与 Reanimation 资源命名、`RENDER_GROUP_*`、图层偏移强绑定。
- Boss 全链路（`UpdateBoss` 及其十余个子函数）：高度特化于最终 Boss 的时序与资源。
- 音效/粒子触发点（`AnimateChewSound`/`DoDaisies` 等）：纯表现层，无复用价值。

### 总结

`Zombie` 模块整体**架构清晰、职责分明**：数据（`gZombieDefs`）与逻辑（`Zombie` 类）分离，状态机（`mZombiePhase`/`mZombieHeight`）驱动，伤害分层结算，特殊僵尸各自独立 `UpdateXxx` 并由 `UpdateActions` 统一分发。最适合复用的部分是**数据表、伤害管线、死亡-掉落链路与坐标/碰撞换算**；最需要参考而非照搬的部分是**各特殊僵尸状态机与 Boss 逻辑**。
